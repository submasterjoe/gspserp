Webhook URL

Configure your bridge / middleware to send POST requests with a JSON body to: If your device is set to T&A push (ADMS), it typically sends data to ZKTeco cloud/WDMS instead of directly calling this webhook, so you still need a translator (this can be a polling bridge every 30–60 seconds).

{% if zkteco_secret_configured %}

Server requires header X-ZKTeco-Secret (value is set in server .env as ZKTECO_WEBHOOK_SECRET).

{% else %}

No webhook secret is set — requests are accepted without a header. Set ZKTECO_WEBHOOK_SECRET in .env for production.

{% endif %}

If the URL shows localhost, set PUBLIC_BASE_URL=https://your-domain.com in .env so the real public address is shown here.

Example JSON body:

{
  "terminal_sn": "DEVICE_SERIAL_FROM_ZK",
  "emp_code": "123",
  "event_type": "clock_in",
  "punch_time": "2026-04-03T10:30:00+00:00"
}

event_type can be clock_in / clock_out (or common aliases like in / out). punch_time can be ISO string or Unix timestamp.

ZKTeco ADMS bridge payloads are also accepted: deviceId → terminal, userId → emp code, timestamp → time, status e.g. check-in / check-out.
